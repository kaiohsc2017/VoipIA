Guia de Implantação — AsteriskIA

Instalação completa do stack AsteriskIA do zero: desde o primeiro login no servidor até o acesso à aplicação em produção com HTTPS, incluindo o módulo de Agentes.

SO Ubuntu 22.04
RAM mínima 8 GB
CPU mínima 4 vCPUs
Disco mínimo 40 GB
Tempo estimado 45–60 min

PRÉ Requisitos

🖥️ Servidor

VPS ou servidor dedicado com Ubuntu 22.04 LTS (64-bit). Acesso root ou sudo obrigatório.

🌐 Domínio

Um domínio com DNS apontando para o IP do servidor. O Caddy emite o certificado SSL automaticamente.

🔑 Acesso SSH

Chave SSH ou senha para acesso inicial. Recomendamos autenticação por chave.

📦 Credenciais

Token do GitHub (PAT) para clonar o repositório privado. Google Gemini API Key (opcional para IA).

Portas que devem estar abertas no firewall/VPS

PortaProtocoloServiçoObrigatório
22TCPSSH — acesso ao servidorSim
80TCPHTTP — redirecionamento HTTPS + ACME challengeSim
443TCPHTTPS — aplicação webSim
5060UDP/TCPSIP — tronco de telefoniaVoIP
10000–10100UDPRTP — mídia de áudioVoIP
8088TCPWebSocket Asterisk (WebRTC)WebRTC
⚠️

DNS antes de começar: configure o registro A do seu domínio apontando para o IP do servidor antes de iniciar a instalação. O Caddy precisa resolver o domínio para emitir o certificado SSL automaticamente via Let's Encrypt.

PASSO 1 Acesso ao Servidor

1.1 — Conectar via SSH

Do seu computador local, abra um terminal e conecte ao servidor:

Terminal localseu-computador $
# Com autenticação por senha
ssh root@SEU_IP_DO_SERVIDOR

# Com autenticação por chave SSH (recomendado)
ssh -i ~/.ssh/sua_chave.pem root@SEU_IP_DO_SERVIDOR

# Se usar porta SSH diferente da 22
ssh -p 2222 root@SEU_IP_DO_SERVIDOR
ℹ️

Na primeira conexão, o SSH pergunta sobre a autenticidade do host. Digite yes e pressione Enter para aceitar e salvar a chave do servidor.

PASSO 3 Instalação do Docker

ℹ️

Instalar o Docker oficial do repositório da Docker Inc., não via apt install docker.io (versão desatualizada do Ubuntu). O AsteriskIA requer Docker 24+ e Compose v2.

3.1 — Adicionar repositório oficial Docker

Servidor
# Adiciona chave GPG oficial do Docker
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg

# Adiciona repositório Docker
echo \
  "deb [arch=$(dpkg --print-architecture) \
  signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" \
  | tee /etc/apt/sources.list.d/docker.list > /dev/null

# Atualiza e instala Docker + Compose Plugin
apt-get update -y
apt-get install -y \
  docker-ce \
  docker-ce-cli \
  containerd.io \
  docker-buildx-plugin \
  docker-compose-plugin

PASSO 4 Instalação do Caddy

O Caddy é o proxy reverso que gerencia HTTPS automático (Let's Encrypt) e roteia tráfego para os containers Docker. É instalado no host, fora do Docker.

4.1 — Instalar Caddy

Servidor
# Adiciona repositório oficial do Caddy
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg

curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | tee /etc/apt/sources.list.d/caddy-stable.list

apt-get update -y && apt-get install -y caddy

# Verifica versão
caddy version
v2.8.4 h1:q3...

4.2 — Adicionar Caddy à rede Docker

O Caddy precisa enxergar os containers. Para isso, criamos a rede Docker antes de subir os serviços e adicionamos o Caddy a ela:

Servidor
# Cria a rede Docker que os containers usam
docker network create asteriskia-net 2>/dev/null || true

# Descobre o nome do processo caddy no namespace de rede
# (necessário para comunicação host → containers)
ip addr show docker0
ℹ️

O Caddy roda no host e acessa os containers pelo nome (agents-backend:8000, asteriskia-frontend:80). Para isso funcionar, o Caddy precisa usar a bridge network do Docker. Configuraremos isso no Caddyfile.

4.3 — Configurar Caddyfile

Copiaremos o Caddyfile do repositório após clonar o projeto. Por ora, paramos o serviço padrão:

Servidor
systemctl stop caddy
systemctl enable caddy

7.1 — Criar estrutura de diretórios

7.2 — Instalar Caddyfile do projeto

Servidor
# Substitui o Caddyfile padrão pelo do projeto
cp /opt/AsteriskIA/Caddyfile /etc/caddy/Caddyfile

# Edita o Caddyfile para colocar seu domínio real
nano /etc/caddy/Caddyfile
📝

No Caddyfile, substitua app.voiphash.com.br pelo seu domínio real em todas as ocorrências. Salve com Ctrl+O, Enter, Ctrl+X.

7.3 — Configurar Caddy para acessar rede Docker

O Caddy no host precisa resolver os nomes dos containers. Adicione o IP da bridge Docker ao Caddy:

Servidor
# Verifica IP da bridge Docker (geralmente 172.17.0.1)
docker network inspect asteriskia-net 2>/dev/null \
  | grep '"Gateway"' | head -1
                "Gateway": "172.20.0.1"

# Se a rede ainda não existir, cria
docker network create asteriskia-net 2>/dev/null; true

# Adiciona resolução dos containers no /etc/hosts do host
# (alternativa: usar IP diretamente no Caddyfile)
# Os containers estarão disponíveis após o docker compose up
ℹ️

O Caddy usa os nomes de container (agents-backend, asteriskia-frontend) que o Docker resolve internamente via DNS. Para o Caddy do host enxergar esses nomes, ele precisa usar o servidor DNS do Docker (127.0.0.11). Isso é gerenciado automaticamente quando o Caddy é iniciado após os containers estarem rodando.

7.4 — Configurar systemd do Caddy

Servidor

PASSO 12 Configurar Firewall (UFW)

Servidor
# Regras básicas
ufw default deny incoming
ufw default allow outgoing

# SSH — NUNCA bloqueie antes de ter acesso garantido
ufw allow 22/tcp

# HTTP e HTTPS (Caddy)
ufw allow 80/tcp
ufw allow 443/tcp

# SIP e RTP (VoIP)
ufw allow 5060/udp
ufw allow 5060/tcp
ufw allow 10000:10100/udp

# WebSocket Asterisk (WebRTC)
ufw allow 8088/tcp

# Ativa o UFW
ufw --force enable

# Verifica regras
ufw status verbose
🚨

ATENÇÃO: Execute ufw allow 22/tcp antes de ufw enable. Se bloquear o SSH antes de liberar a porta, você perderá o acesso ao servidor e precisará usar o console de emergência do provedor.

Troubleshooting

Container não inicia

Diagnóstico
# Ver logs do container com erro
docker logs asteriskia-backend --tail=50

# Ver eventos recentes do Docker Compose
docker compose events --since 5m

# Reiniciar container específico
docker compose restart backend

Erro de Flyway (migrations)

Solução
# Verificar histórico do Flyway
docker exec asteriskia-postgres psql -U asteriskia -d asteriskia \
  -c "SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank;"

# Se necessário, reparar checksums (ver documentação)

Caddy não emite certificado SSL

Diagnóstico
# Verifica logs do Caddy
journalctl -u caddy -n 50 --no-pager

# Problemas comuns:
# 1. DNS não propagou — aguarde até 24h após configurar o registro A
# 2. Porta 80 bloqueada — verifique UFW e painel do provedor
# 3. Domínio incorreto no Caddyfile

# Testar resolução DNS
dig +short app.seudominio.com
200.150.100.50

Agentes API retornando 401

Diagnóstico
# Confirma que BACKEND_JWT_SECRET está idêntico nos dois serviços
grep BACKEND_JWT_SECRET /opt/AsteriskIA/.env
docker exec asteriskia-agents-api env | grep BACKEND_JWT_SECRET
# Os valores devem ser iguais

Ver todos os logs de uma vez

Servidor
# Todos os containers em tempo real
docker compose logs -f --tail=20

# Apenas erros
docker compose logs --tail=100 2>&1 | grep -i "error\|exception\|failed"

Manutenção e Atualizações

Atualizar para nova versão

Servidor
cd /opt/AsteriskIA

# Puxa novas versões
git pull origin main

# Rebuild e reinicia containers modificados
docker compose build --no-cache agents-backend
docker compose up -d agents-backend

# Frontend (só restart — volume montado)
docker compose restart agents-frontend

Backup do banco de dados

Servidor
# Backup do banco principal
docker exec asteriskia-postgres pg_dump -U asteriskia asteriskia \
  | gzip > /opt/backup/asteriskia_$(date +%Y%m%d).sql.gz

# Backup do banco dos agentes
docker exec asteriskia-agents-db pg_dump -U agents agentsdb \
  | gzip > /opt/backup/agentsdb_$(date +%Y%m%d).sql.gz

Monitorar recursos

Servidor
# Uso de recursos por container
docker stats --no-stream

# Espaço em disco
df -h / && docker system df

Checklist pós-instalação

  • Todos os containers com status running (docker compose ps)
  • HTTPS funcionando em https://app.seudominio.com
  • Login no AsteriskIA Telecom com sucesso
  • Login no AsteriskIA Agentes com sucesso
  • Health check respondendo: /agents/api/system/health
  • Primeiro servidor SSH cadastrado e testado
  • Primeiro agente criado e executado manualmente
  • UFW ativo com regras corretas
  • Backup agendado (cron)
  • Uptime monitor externo configurado no health check
