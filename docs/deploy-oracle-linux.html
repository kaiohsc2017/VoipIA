Guia de Implantação — AsteriskIA

Instalação completa do stack AsteriskIA em Oracle Linux 9, abordando as diferenças críticas em relação ao Ubuntu: SELinux, firewalld, dnf, podman vs docker e configurações específicas do ambiente RHEL-compatible.

SO Oracle Linux 9
RAM mínima 8 GB
CPU mínima 4 vCPUs
Disco mínimo 40 GB
Tempo estimado 60–80 min

⚡ Diferenças Críticas: Ubuntu vs Oracle Linux 9

Se você já conhece o guia Ubuntu, leia esta seção primeiro. Oracle Linux 9 tem diferenças fundamentais que mudam vários passos da instalação.

AspectoUbuntu 22.04Oracle Linux 9
Gerenciador de pacotes apt-get dnf (substituiu yum)
Firewall padrão UFW (ufw) firewalld (firewall-cmd)
SELinux Não instalado Ativo por padrão — precisa configurar
Docker Repositório Docker Inc. Repositório Docker Inc. ou Podman nativo (usaremos Docker)
systemd Igual Igual
cgroup v2 Padrão Padrão no OL9 — Docker 20+ compatível
Caddy repositório .deb via cloudsmith .rpm via cloudsmith
Usuário padrão ubuntu ou root opc (Oracle Cloud) ou root
🔴

SELinux é o maior desafio: No Oracle Linux 9, o SELinux bloqueia silenciosamente conexões Docker, acesso a volumes e bind mounts. A maioria dos problemas de "funciona no Ubuntu mas não no OL9" é SELinux. Veja a seção dedicada.

PASSO 3 SELinux e Firewalld

🚨

Não pule esta seção. SELinux e firewalld são as principais causas de falha em instalações Oracle Linux. Configure-os corretamente antes de instalar o Docker.

3.1 — Configurar SELinux

O SELinux pode ser configurado em três modos. Recomendamos Permissive durante a instalação e depois ajustar as políticas para Enforcing:

Servidor
# Ver status atual do SELinux
getenforce
Enforcing

# Opção A (Recomendada para produção): manter Enforcing e adicionar políticas
# Opção B (Mais simples): colocar em Permissive (loga mas não bloqueia)

# Para instalar em modo Permissive (mais fácil, menos seguro)
setenforce 0
sed -i 's/^SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config

# Confirma
getenforce
Permissive
⚠️

Se quiser manter Enforcing (mais seguro), execute estas políticas adicionais após instalar o Docker e subir os containers:

Servidor — políticas SELinux para Docker (Enforcing)
# Permite Docker acessar volumes bind-mounted
setsebool -P container_manage_cgroup on

# Permite containers fazer conexões de rede
setsebool -P container_connect_any on

# Permite Caddy (processo do host) se comunicar com sockets
setsebool -P httpd_can_network_connect on

# Aplica contexto correto ao diretório do projeto
chcon -Rt container_file_t /opt/AsteriskIA
chcon -Rt container_file_t /var/asteriskia

# Verifica negações SELinux (após subir os containers)
ausearch -m avc -ts recent | audit2allow -a

3.2 — Configurar Firewalld

Oracle Linux usa firewall-cmd em vez do ufw do Ubuntu:

Servidor
# Verifica status do firewalld
systemctl is-active firewalld
active

# Abre portas necessárias
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --permanent --add-service=ssh

# SIP e RTP (VoIP)
firewall-cmd --permanent --add-port=5060/udp
firewall-cmd --permanent --add-port=5060/tcp
firewall-cmd --permanent --add-port=10000-10100/udp

# WebSocket Asterisk (WebRTC)
firewall-cmd --permanent --add-port=8088/tcp

# Aplica as regras
firewall-cmd --reload

# Verifica regras ativas
firewall-cmd --list-all
public (active)
  target: default
  services: cockpit dhcpv6-client http https ssh
  ports: 5060/udp 5060/tcp 10000-10100/udp 8088/tcp

3.3 — Desabilitar firewall do Oracle Cloud (se usar OCI)

No Oracle Cloud Infrastructure, há dois firewalls: o do SO (firewalld) e as Security Lists / Network Security Groups da VCN. Ambos precisam liberar as portas.

☁️

No console OCI: Networking → Virtual Cloud Networks → sua VCN → Security Lists → Default Security List. Adicione Ingress Rules para as portas 80, 443, 5060, 8088 e 10000-10100.

PASSO 4 Instalação do Docker

🔴

Use Docker, não Podman. Oracle Linux 9 vem com Podman pré-instalado, mas o AsteriskIA usa Docker Compose v2 com funcionalidades específicas do Docker. Instalaremos o Docker oficial.

4.1 — Remover Podman (se conflitar)

Servidor
# Verifica se podman está instalado
which podman && podman --version
/usr/bin/podman
podman version 4.6.1

# O Podman não conflita diretamente com Docker, mas para evitar confusão:
dnf remove -y podman podman-docker 2>/dev/null; true

4.2 — Adicionar repositório oficial Docker

Servidor
# Adiciona repositório Docker para RHEL/CentOS/Oracle Linux
dnf config-manager \
  --add-repo \
  https://download.docker.com/linux/rhel/docker-ce.repo

# Instala Docker CE + Compose Plugin
dnf install -y \
  docker-ce \
  docker-ce-cli \
  containerd.io \
  docker-buildx-plugin \
  docker-compose-plugin

4.3 — Configurar e iniciar Docker

Servidor
# Habilita e inicia o Docker
systemctl enable --now docker

# Verifica
systemctl is-active docker
active

docker --version
Docker version 26.1.4, build 5650f9b

docker compose version
Docker Compose version v2.27.1

4.4 — Configurar SELinux para Docker (se Enforcing)

Servidor
# Instala módulo SELinux para containers
dnf install -y container-selinux

# Configura daemon Docker para usar SELinux
mkdir -p /etc/docker
cat > /etc/docker/daemon.json << 'EOF'
{
  "selinux-enabled": true,
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "50m",
    "max-file": "3"
  }
}
EOF

systemctl restart docker

# Testa
docker run --rm hello-world
Hello from Docker!

5.2 — Configurar SELinux para o Caddy

Servidor
# Permite Caddy abrir portas privilegiadas (80, 443)
setsebool -P httpd_can_network_connect on

# Permite Caddy conectar a sockets de rede arbitrários (containers)
setsebool -P httpd_can_network_relay on

# Cria diretório de dados do Caddy com contexto correto
mkdir -p /var/lib/caddy
chown caddy:caddy /var/lib/caddy
semanage fcontext -a -t httpd_var_lib_t '/var/lib/caddy(/.*)?'
restorecon -Rv /var/lib/caddy

5.3 — Parar serviço enquanto configura

Servidor
systemctl stop caddy
systemctl enable caddy

Troubleshooting Específico Oracle Linux 9

Container não consegue acessar volume (Permission denied)

Causa provável: SELinux
# Verifica negações SELinux
ausearch -m avc -ts recent | grep denied

# Solução rápida: adiciona :z ao volume no docker-compose.yml
# Ex: ./env:/opt/AsteriskIA/env:ro,z
# O :z faz o Docker rotular o volume com o contexto SELinux correto

# Ou reaplica contexto manualmente
chcon -Rt container_file_t /opt/AsteriskIA
chcon -Rt container_file_t /var/asteriskia

Caddy não consegue conectar ao container

Causa: SELinux ou firewalld bloqueando
# Libera Caddy conectar a qualquer porta de rede
setsebool -P httpd_can_network_connect on
setsebool -P httpd_can_network_relay on

# Verifica se firewalld bloqueia tráfego interno Docker
firewall-cmd --add-interface=docker0 --zone=trusted --permanent
firewall-cmd --reload

Docker não inicia (cgroup v2)

Solução
# Verifica versão cgroup
stat -fc %T /sys/fs/cgroup/
cgroup2fs

# Docker 20+ suporta cgroup v2 nativamente
# Se houver erro, verifica se docker.service está com override
systemctl show docker | grep ExecStart

# Reinicia com configuração limpa
systemctl daemon-reload
systemctl restart docker

Erro de Flyway no backend Spring Boot

Diagnóstico e solução
# Ver erro completo
docker logs asteriskia-backend --tail=50 | grep -A5 "Flyway\|migration"

# Conecta no banco para verificar histórico
docker exec -it asteriskia-postgres psql \
  -U asteriskia -d asteriskia \
  -c "SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank;"

Porta 80/443 bloqueada (OCI)

Diagnóstico OCI
# Testa conectividade da porta 80 externamente
curl -v http://app.seudominio.com 2>&1 | head -20

# Se não conectar, verifique:
# 1. Security Lists na VCN do OCI (console web)
# 2. Network Security Groups (se usar NSG)
# 3. firewalld local:
firewall-cmd --list-all

# Libera explicitamente via zona pública
firewall-cmd --zone=public --add-service=http --permanent
firewall-cmd --zone=public --add-service=https --permanent
firewall-cmd --reload

Ver logs completos de diagnóstico

Servidor
# Todos os containers
docker compose logs --tail=30 2>&1

# Negações SELinux nas últimas 10 minutos
ausearch -m avc -ts recent 2>/dev/null | audit2why

# Caddy
journalctl -u caddy -n 50 --no-pager

# Docker daemon
journalctl -u docker -n 30 --no-pager

# Banco principal

  | gzip > /opt/backup/asteriskia_$(date +%Y%m%d_%H%M).sql.gz

docker exec asteriskia-agents-db pg_dump -U agents agentsdb \
  | gzip > /opt/backup/agentsdb_$(date +%Y%m%d_%H%M).sql.gz

ls -lh /opt/backup/

Agendar backup automático (cron)

Servidor
crontab -e
# Adicione estas linhas:
0 2 * * * docker exec asteriskia-postgres pg_dump -U asteriskia asteriskia | gzip > /opt/backup/asteriskia_$(date +\%Y\%m\%d).sql.gz
0 2 * * * docker exec asteriskia-agents-db pg_dump -U agents agentsdb | gzip > /opt/backup/agentsdb_$(date +\%Y\%m\%d).sql.gz
0 3 * * 0 find /opt/backup -name "*.sql.gz" -mtime +30 -delete

Checklist pós-instalação Oracle Linux 9

  • SELinux configurado (Permissive ou Enforcing com políticas)
  • Firewalld com portas 80, 443, 22, 5060, 10000-10100 abertas
  • Security Lists do OCI liberadas (se Oracle Cloud)
  • Todos os containers com status running
  • HTTPS funcionando com certificado válido
  • Login no AsteriskIA Telecom com sucesso
  • Login no AsteriskIA Agentes com sucesso
  • Health check respondendo: /agents/api/system/health
  • Contexto SELinux aplicado em /opt/AsteriskIA e /var/asteriskia
  • Backup agendado via cron
  • Uptime monitor externo no health check
