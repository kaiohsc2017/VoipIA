VoipIA v3.1 — Guia de Implantação

Stack VoIP + IA completo: Asterisk 21 LTS (G.729+G.711), Spring Boot 3.3, React 18, Python asyncio, PostgreSQL 16 e Multi-provider AI com fallback automático (Gemini, Anthropic, OpenAI, ElevenLabs, Grok, Perplexity, Ollama).

OSUbuntu 22 / 24
Asterisk21 LTS
CodecsG.729 + G.711
IAMulti-provider
Build~25 min

PRÉ Requisitos

CPU

4 vCPUs mínimo

RAM

8 GB mínimo (16 GB recomendado)

Disco

40 GB SSD (50+ para gravações)

IP Público

Fixo — obrigatório para RTP/WebRTC

DNS

Domínio apontando para o servidor

Acesso

Root ou sudo sem senha

⚠️

SIP_PUBLIC_IP é crítico. O Asterisk precisa do IP público para anunciar os candidatos RTP/ICE corretamente. Sem ele, as chamadas conectam mas não há áudio — o browser WebRTC não consegue alcançar o IP interno Docker.

Portas necessárias

ℹ️

TURN (coturn) é o relay usado quando STUN não basta pra atravessar NAT (ex: NAT simétrico, redes corporativas restritivas) — sem essas portas abertas, o softphone WebRTC pode falhar em conectar áudio para uma fração dos usuários, mesmo com SIP_PUBLIC_IP correto.

  docker-buildx-plugin docker-compose-plugin

03 Caddy (HTTPS)

ℹ️

O Caddy faz parte do docker compose — não é necessário instalá-lo separadamente. Ele sobe automaticamente no passo 06 (Build e Inicialização), obtém o certificado TLS via Let's Encrypt e configura as rotas automaticamente.

✅

Caminho recomendado: use bash install.sh (raiz do repositório) em vez de editar o .env manualmente — ele gera todas as credenciais acima automaticamente (senhas, JWT secret, TURN, ramais SIP), detecta o IP público e já configura o firewall. Os passos manuais desta página servem como referência/troubleshooting, não como o fluxo principal.

ℹ️

A API Key da IA é configurada pelo painel (Settings → Inteligência Artificial), não no .env. Os modelos são gerenciados no banco — alterar no .env não tem efeito.

URA — Ramal 1000

Disque 1000 de qualquer ramal para acessar a URA Jira. Fluxo: Answer → Playback(silence/3) → AudioSocket → TTS boas-vindas → coleta de dados → Jira.

REF Firewall (UFW)

bash
ufw --force reset
ufw default deny incoming && ufw default allow outgoing
ufw allow ssh
ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 443/udp
ufw allow 5060/udp && ufw allow 5060/tcp
ufw allow 8088/tcp
ufw allow 16000:16500/udp
ufw allow 3478/udp && ufw allow 3478/tcp
ufw allow 5349/tcp && ufw allow 5349/udp
ufw allow 49152:49652/udp
ufw --force enable
⚠️

Se o servidor está atrás de um firewall de cloud (AWS Security Groups, Oracle NSG), abra as mesmas portas também no nível do cloud provider — especialmente 16000-16500/UDP (RTP) e 49152-49652/UDP (relay TURN).

REF Troubleshooting

Chamada conecta mas sem áudio

bash
# 1. Verifica SIP_PUBLIC_IP (causa mais comum)
docker exec voipia-asterisk grep "external_media_address" /etc/asterisk/pjsip.conf
# Se vazio: injeta o IP e faz module reload res_pjsip.so

# 2. Portas RTP abertas no host
ss -ulnp | grep -E "1000[0-9]|1001[0-9]"

URA não fala / erro 404 STT

bash
docker logs -f voipia-ai-agent 2>&1 | tail -30
# 404 gemini-2.0-flash → descontinuado. Trocar para gemini-2.5-flash no painel.
# 400 TTS INVALID_ARGUMENT → modelo TTS deve terminar em -tts
# STT transcrevendo ruído → _POST_SPEAK_BUFFER_SECS muito pequeno (deve ser 2.0)

Gravação não aparece no dashboard

bash
docker exec voipia-asterisk ls /var/spool/asterisk/monitor/*.wav 2>/dev/null | head -5
docker exec voipia-backend ls /var/spool/asterisk/monitor/*.wav 2>/dev/null | head -5
# Ambos devem listar os mesmos arquivos (volume compartilhado)

Flyway migration falhou

bash
docker exec voipia-postgres psql -U asteriskia -d asteriskia \
  -c "DELETE FROM flyway_schema_history WHERE success=false;"
docker compose restart backend

REF Manutenção

Atualizar sistema
bash /opt/VoipIA/install.sh --update
Recarregar dialplan (sem restart)
docker cp asterisk/config/extensions.conf voipia-asterisk:/etc/asterisk/extensions.conf
docker exec voipia-asterisk asterisk -rx "dialplan reload"
Recarregar PJSIP (sem restart)
docker exec voipia-asterisk asterisk -rx "module reload res_pjsip.so"
Recarregar Caddyfile (socket Unix, não TCP:2019)
curl --unix-socket /opt/VoipIA/caddy-admin/admin.sock http://localhost/load \
  -H "Content-Type: text/caddyfile" \
  --data-binary @/opt/VoipIA/Caddyfile
Backup do banco
docker exec voipia-postgres pg_dump -U asteriskia asteriskia \
  | gzip > /opt/backups/asteriskia_$(date +%Y%m%d_%H%M).sql.gz
